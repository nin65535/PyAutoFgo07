# コードレビュー方針

## 対象と進め方

R01〜R35で実装した現行アプリ全体を対象とする。最初のレビューはCodexが読み取りと検証を行い、コードの修正は指摘を整理した後の別作業とする。レビュー開始時にブランチ、作業ツリー、基準コミットを記録し、差分がある場合はその影響も確認する。旧アプリ `C:\2406_autoplay` は仕様の参照に限り、変更しない。

設計資料、[ロードマップ](roadmap.md)、[作業詳細](work-details.md)、[運用・復旧手順](operations.md)と実装を照合する。コードを読んで問題の成立条件を追い、可能な範囲でテストまたは再現手順によって確かめる。

## 確認する順序

1. **自動操作の安全性**：通常停止・緊急停止・一時停止、指令キュー、Chrome終了とSSE切断、キャンセル後のクリックやキー入力の有無を確認する。
2. **カード認識とデータ保全**：認識失敗時の扱い、カード選択、参照保存の整合性、実行開始時の参照スナップショット、プレイヤーとサンプラーの同時起動を確認する。
3. **画面とAPIの整合性**：All/Wave実行、命令の重複送信、SSEイベントと再接続、接続保護、入力検証、エラー表示を確認する。
4. **配布と運用**：起動・終了・復旧手順と実装の一致、管理対象データとローカルデータの扱いを確認する。

特に、停止後も自動操作が続く経路や、認識失敗から意図しないカードを選ぶ経路を優先する。

## コードレビューロードマップ

各項目はコードの追跡、関連テストと検証結果の確認、指摘事項の記録まで行って完了とする。修正作業はレビュー結果を整理した後に計画する。領域をまたぐ問題は該当する項目に記録し、最後の横断確認でも扱う。

- [x] CR01 停止と実行制御：指令キュー、通常停止・緊急停止・一時停止、Chrome終了、SSE切断を確認する。キャンセル後にクリックやキー入力が続く経路を優先する。結果は[CR01レビュー](code-reviews/2026-09-27-CR01-stop-and-execution-control.md)に記録。
- [x] CR02 カード認識とデータ：カードの検出・選択、認識失敗時の扱い、参照保存、実行開始時のスナップショット、サンプラーとの同時起動を確認する。結果は[CR02レビュー](code-reviews/2026-09-27-CR02-card-recognition-and-data.md)に記録。
- [ ] CR03 フロントエンドとAPI：All/Wave実行、命令の重複送信、状態同期、接続保護、入力検証、エラー表示を確認する。
- [ ] CR04 起動・運用と横断確認：配布・起動・終了・復旧手順と実装を照合し、CR01〜CR03の境界をまたぐ不具合や見落としを確認する。全体の検証結果と残る制約をまとめる。

## 検証

既存の単体テスト、静的解析、フォーマット確認、フロントエンドのビルドを実行し、結果を記録する。バックエンドのPythonは必ずプロジェクト直下の `.venv` を使用する。

```powershell
npm run test:frontend
.\.venv\Scripts\python.exe -m pytest backend/tests
npm run lint
npm run format:check
npm --prefix frontend run build
```

OS資産を使う結合テストや実画面操作は、実行環境と対象画面を確認した上で別途行う。実行しなかった検証と、その理由を報告する。

## 結果の報告

指摘は重大度順に並べ、各項目に該当ファイルと行、成立条件または再現手順、影響、修正案を記載する。重大度は以下を目安とする。

- **高**：意図しない自動操作、停止不能、データ破損など、利用を止めて修正すべき問題。
- **中**：通常の操作で機能が失敗する、または復旧が難しくなる問題。
- **低**：限定的な条件で起きる問題や保守上の欠陥。

確認できた不具合と、再現できていない懸念を分ける。指摘がない場合も、その旨と確認範囲、検証結果、残る制約を記載する。修正に進む場合は、指摘ごとに回帰テストと修正を行い、該当する検証を再実行する。
