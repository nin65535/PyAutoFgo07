# R15 実装ログ — 接続保護と入力検証

- 実施日: 2026-09-25
- 対象: R15「接続保護と入力検証を実装する」
- 状態: 完了

## 実施内容

### フロントエンド

- Chrome起動URLのフラグメントから起動セッション情報を一度だけ取得し、取得直後に
  アドレス欄から削除する処理を追加した。
- REST APIとSSEの全要求へセッションIDとBearerトークンを付与する共通処理を追加した。
- 資格情報の取得、フラグメント消去、認証ヘッダー生成を検証するテストを追加した。

### バックエンド

- 起動ごとにUUIDのセッションIDと推測困難なセッショントークンを生成するようにした。
- 全REST APIとSSEでセッションIDおよびBearerトークンを検証し、固定時間比較を使用した。
- 専用フロントエンド以外のOriginを拒否し、CORSの許可Origin、メソッド、ヘッダーを限定した。
- Chrome起動URLへHTTPログに送信されないフラグメントとして資格情報を引き渡すようにした。
- 終了処理でトークンを無効化するようにした。
- API本文を64 KiB、要求対象を2,048文字、シナリオJSONを1 MiBへ制限し、未知のクエリと
  不要な本文を拒否した。既存のstrictなPydanticモデルと値域制約も維持した。
- FastAPIの待受ホスト設定をループバックアドレスだけに制限した。
- 認証失敗、不正Origin、CORS、サイズ超過、未知入力、トークン無効化、非ローカルホスト拒否の
  テストを追加した。

### プロジェクト共通

- 接続境界、資格情報の受け渡し、入力上限を
  `documents/design/connection-security-and-input-validation.md` に記録した。
- `documents/roadmap.md` のR15を完了へ更新した。
