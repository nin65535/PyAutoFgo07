# R22 実装ログ — 攻撃命令の呼び出し名分離

- 実施日: 2026-09-27
- 対象: roadmap2保留課題「攻撃命令の呼び出し名を分離する」（R22仕様の改訂）
- 状態: 完了

## 実施内容

### フロントエンド

- `attack(...)` は0～3個の宝具番号だけを受け付け、文字列指定を拒否するようにした。
- `attack_cards(...)` を追加し、カード指定を独立した型付きコマンドにした。
- 実行時に `attack_cards` へ交代後の前衛名を付与するようにした。
- 構文と実行経路のテストを更新した。

### バックエンド

- `attack` と `attack_cards` のモデルとハンドラーを分離し、型の混用を拒否するようにした。
- APIの受理・拒否とカード指定検証のテストを更新した。

### プロジェクト共通

- `00 test1.json` の文字列指定を新構文へ変更した。
- R22設計文書に旧文字列形式の拒否、両方式の使い分けと処理時間の差を記録した。
- `roadmap2.md` の保留課題を完了にした。

## 検証結果

- フロントエンド: ビルド成功、ESLint成功、Prettier成功、Vitest 64件成功。
- バックエンド: pytest全130件成功、Ruff lint・format成功。
- `git diff --check` 成功。

## 補足

- 旧文字列形式 `attack('N0','B1','')` は自動変換せず、シナリオ検証時に拒否する。`attack_cards(...)` へ書き換える。
- 数値指定の `attack` はカード画像認識を省くため、カード希望が不要なときの高速な方式として維持する。`attack_cards` の所要時間は画像取得・照合環境に依存し、固定値は保証しない。
- ビルドとVitest、pytest全件はサンドボックスの子プロセス・一時ディレクトリ制限を避けるため権限付きで実行した。
- 旧アプリは変更していない。
