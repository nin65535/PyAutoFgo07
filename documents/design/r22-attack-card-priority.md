# R22 攻撃カードの優先順位と互換仕様

## 対象と記法

操作手順JSONの `commands` では、宝具番号のみを指定する `attack()` / `attack(0,1)` と、カード3枚を個別に指定する `attack_cards(...)` を使い分ける。JSONの `schemaVersion` は `1` のままとする。

```text
attack_cards('N1','B1','B1')
        1枚目 2枚目 3枚目
```

各引数はカード1枚目、2枚目、3枚目に対応する。`attack_cards` の引数は1～3個の単一引用符で囲んだ文字列とし、指定しない枠は空文字列 `''` として扱う。`attack_cards('N1')` は `attack_cards('N1','','')` と同じ意味である。途中の枠だけ省略する場合は `attack_cards('','B1','')` のように明示する。命令文字列内の空白は許可しない。

各枠では宝具と通常攻撃を同時に指定できない。宝具を選ぶ枠には `N0`～`N2` の1個だけを指定する。通常攻撃を選ぶ枠には、`B1A1Q1B0B2` のように2文字単位の希望を連結するか、空文字列を指定する。`B`・`A`・`Q` はBuster・Arts・Quickを表す。数字0～2は攻撃時点の前衛位置（0始まり）を表し、`swap()` 後は交代後の位置で解釈する。`members` のキャラクター名と前衛位置の対応は、シナリオ先頭の配置と対象命令までに記載された `swap()` の累積結果から求める。WaveN単独実行でも先行Waveの `swap()` を前衛計算に反映するが、その命令自体は再送しない。実画面の前衛は先行Waveの交代後の状態を前提とする。

同じ宝具を複数の枠に指定できない。通常カードの希望は同じ2文字を複数の枠や1つの枠内に記述できる。構文に合わない指定、`N0B1` のように1枠で宝具と通常攻撃を混ぜた指定、宝具の重複はシナリオ検証時に拒否する。命令文字列には既存の上限100文字を適用する。

## 選択規則

宝具指定の枠は、その前衛の宝具を選ぶ。使用可能な宝具が画面にない場合は警告を出して攻撃指令を停止する。別のカードによる代替は行わない。宝具の可否と通常カードの認識結果を、可能な限りカードクリック前に検証する。警告の表示と失敗理由の記録方法はR29で扱う。

通常カードの割り当ては**3枚目、2枚目、1枚目**の順に決める。まず各枠の希望文字列を左から評価し、未割り当ての5枚のうち一致するカードを1枚確保する。同じ希望に複数枚が一致する場合は画面の左側を選ぶ。候補がなければその枠の次の希望を試す。宝具の枠はこの処理の対象外とする。

明示した希望の割り当てが全枠で終わってから、候補が見つからなかった枠と空文字列の枠を、**1枚目、2枚目、3枚目**の順に未割り当ての通常カードの左端から埋める。確定した3枚も**1枚目、2枚目、3枚目**の順にクリックする。希望カードの確保だけに3枚目優先を適用し、空文字列のみの従来動作は維持する。

例として `attack_cards('N1','B1','B1')` で前衛1のBカードが1枚だけなら、3枚目の希望がそのカードを確保する。2枚目は残った通常カードの左端で埋め、クリック順は宝具1、補完した通常カード、B1となる。

通常カードの希望がある場合、色またはキャラクターの判定が不明・曖昧なカードを「一致なし」とみなさない。5枚のいずれかが判定不能なら、通常カードのクリック前に指令を失敗させる。現行の `attack_cards` 実行経路は、全ての通常枠が空文字列の場合も画像認識を行う。認識を省きたい場合は数値指定の `attack` を使用する。

同名のキャラクターが前衛に複数いる場合、名前だけではそのカードの前衛位置を確定できない。区別に必要な識別情報がない間は、そのキャラクターを指す通常カード希望を実行せず失敗させる。前衛位置の追跡に失敗した場合、`members` の名前と認識結果を対応付けられない場合も失敗させる。通常カードの希望を持たない命令では、この照合を要求しない。

## 既存形式と実装境界

既存の `attack()`、`attack(0)`、`attack(2,0)` などは引き続き有効とする。数値引数は1枚目から順に宝具を指定し、残りを通常カードの左端から選ぶ。例えば `attack(2,0)` の選択結果は `attack_cards('N2','N0','')` と同じである。数値指定はカード画像認識を行わないため高速で、宝具指定と左端選択だけでよい場合に使う。`attack_cards` は画面取得・画像認識・照合が加わるため処理時間が長くなる。処理時間は画面取得や認識環境に依存し、固定値は保証しない。旧形式の数値指定シナリオは書き換えない。旧文字列形式 `attack('N0','B1','')` と数値・文字列を混在させた命令は検証時に拒否し、`attack_cards(...)` へ書き換える。

フロントエンドは `attack` を `noblePhantasmIndexes` の型付きコマンド、`attack_cards` を `cardSlots` と攻撃時の `frontMembers` の型付きコマンドへ変換する。バックエンドは型ごとに再検証し、前者を左端選択経路、後者をカード指定経路へ送る。元の命令文字列はバックエンドへ渡さない。カード割り当て処理はR27、画面操作への統合はR28で実装した。
