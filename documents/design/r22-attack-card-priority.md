# R22 攻撃カードの優先順位と互換仕様

## 対象と記法

操作手順JSONの `commands` に、従来の `attack()` / `attack(0,1)` と併せて、カード選択順を表す新記法を追加する。JSONの `schemaVersion` は `1` のままとする。新記法は1個の連結した指定文字列を引数とし、例は `attack(N0B1A1Q1B0B2)` とする。命令文字列内に引用符、空白、カンマは入れない。

新記法は2文字ずつ左から読む。`N0`～`N2` は現在の前衛位置0～2の宝具、`B0`～`B2`・`A0`～`A2`・`Q0`～`Q2` はその前衛のBuster・Arts・Quickカードを意味する。番号は操作手順の初期 `members` 配列番号ではなく、攻撃時点の前衛位置である。`swap()` 後は交代後の前衛位置で解釈する。`members` に記載するキャラクター名と実際の前衛の対応は、開始時の配置と実行済みの `swap()` から求める。

宝具指定は先頭に0～3個を並べ、同じ宝具番号は重複させない。宝具の後に通常カードの希望順を0個以上並べる。宝具指定が通常カード指定の後へ現れる形式は受け付けない。通常カード指定は同じ2文字を繰り返してよい。これは同じ前衛・同じ色のカードを複数枚選びたい場合に使う。指定全体は1組以上、命令文字列の既存の上限100文字以内とする。3枚の選択が確定した時点で残りの希望は評価しない。

例:

| 命令 | 意味 |
| --- | --- |
| `attack(B1A1Q1B0B2)` | 前衛1のB、A、Q、前衛0のB、前衛2のBの順に探す |
| `attack(N2B1A1Q1)` | 前衛2の宝具を選び、残り2枚を指定順に探す |
| `attack(N0N2)` | 前衛0・2の宝具を選び、残り1枚を左端の通常カードで埋める |
| `attack(B1B1)` | 前衛1のBを左から最大2枚選び、残りを左端から埋める |

## 通常カードの選択

宝具を記述順に選択し、残りを通常カードで埋める。通常カードの各希望について、未選択の5枚から、指定した前衛と色に一致するカードを探す。一致するカードが複数ある場合は最も左の1枚を選ぶ。一致しない場合は次の希望へ進む。希望が尽きても3枚に満たない場合、未選択の通常カードを左から選ぶ。既に選んだカードは再選択しない。

通常カードの希望が0個なら画像認識は行わず、従来どおり残りを左から選ぶ。希望がある場合、選択に必要なカードの色・キャラクターが不明な状態を「一致なし」とみなさない。5枚のいずれかの判定が不明・曖昧なら通常カードのクリック前に指令を失敗させる。宝具の指定だけで3枚が埋まる場合は通常カードの認識を必要としない。認識結果と失敗理由の記録方法はR29で扱う。

同名のキャラクターが前衛に複数いる場合、名前だけからそのカードの前衛位置を確定できない。区別に必要な識別情報がない間は、そのキャラクターを指す通常カード希望を実行せず失敗させる。前衛位置の追跡に失敗した場合、`members` の名前と認識結果を対応付けられない場合も失敗させる。通常カードの希望を持たない旧形式では、この照合を要求しない。

## 既存形式と実装境界

既存の `attack()`、`attack(0)`、`attack(2,0)` などは引き続き有効とし、宝具番号の範囲・重複禁止・指定順、残りを左から埋める動作を変えない。旧形式を読み込む際にシナリオファイルを書き換えない。新形式の `N0`～`N2` は旧形式の数値0～2に相当する。`attack(N0N2)` と `attack(0,2)` は同じ選択を指す。

フロントエンドは新形式を構文検証し、2文字単位の順序付き指定として型付きコマンドへ変換する。バックエンドは受信した型付きコマンドを再検証する。元の命令文字列をバックエンドへ渡さない。既存の数値形式は従来の型付きコマンドを維持できる。新形式の型付きコマンドの具体的なフィールドとカード選択アルゴリズムはR27、画面操作への統合はR28で実装する。R22では構文と実行時の意味を確定し、実装コードは変更しない。
