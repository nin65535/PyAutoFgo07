# R22 攻撃カードの優先順位と互換仕様

## 対象と記法

操作手順JSONの `commands` に、従来の `attack()` / `attack(0,1)` と併せて、選択するカード3枚を個別に指定する記法を追加する。JSONの `schemaVersion` は `1` のままとする。

```text
attack('N1','B1','B1')
        1枚目 2枚目 3枚目
```

各引数はカード1枚目、2枚目、3枚目に対応する。新記法の引数は0～3個の単一引用符で囲んだ文字列とし、指定しない枠は空文字列 `''` として扱う。`attack()` は `attack('','','')` と同じ意味である。`attack('N1')` は `attack('N1','','')` と同じ意味である。途中の枠だけ省略する場合は `attack('','B1','')` のように明示する。命令文字列内の空白は許可しない。

各枠では宝具と通常攻撃を同時に指定できない。宝具を選ぶ枠には `N0`～`N2` の1個だけを指定する。通常攻撃を選ぶ枠には、`B1A1Q1B0B2` のように2文字単位の希望を連結するか、空文字列を指定する。`B`・`A`・`Q` はBuster・Arts・Quickを表す。数字0～2は攻撃時点の前衛位置（0始まり）を表し、`swap()` 後は交代後の位置で解釈する。`members` のキャラクター名と実際の前衛の対応は、開始時の配置と実行済みの `swap()` から求める。

同じ宝具を複数の枠に指定できない。通常カードの希望は同じ2文字を複数の枠や1つの枠内に記述できる。構文に合わない指定、`N0B1` のように1枠で宝具と通常攻撃を混ぜた指定、宝具の重複はシナリオ検証時に拒否する。命令文字列には既存の上限100文字を適用する。

## 選択規則

宝具指定の枠は、その前衛の宝具を選ぶ。使用可能な宝具が画面にない場合は警告を出して攻撃指令を停止する。別のカードによる代替は行わない。宝具の可否と通常カードの認識結果を、可能な限りカードクリック前に検証する。警告の表示と失敗理由の記録方法はR29で扱う。

通常カードの割り当ては**3枚目、2枚目、1枚目**の順に決める。まず各枠の希望文字列を左から評価し、未割り当ての5枚のうち一致するカードを1枚確保する。同じ希望に複数枚が一致する場合は画面の左側を選ぶ。候補がなければその枠の次の希望を試す。宝具の枠はこの処理の対象外とする。

明示した希望の割り当てが全枠で終わってから、候補が見つからなかった枠と空文字列の枠を、**1枚目、2枚目、3枚目**の順に未割り当ての通常カードの左端から埋める。確定した3枚も**1枚目、2枚目、3枚目**の順にクリックする。希望カードの確保だけに3枚目優先を適用し、空文字列のみの従来動作は維持する。

例として `attack('N1','B1','B1')` で前衛1のBカードが1枚だけなら、3枚目の希望がそのカードを確保する。2枚目は残った通常カードの左端で埋め、クリック順は宝具1、補完した通常カード、B1となる。

通常カードの希望がある場合、色またはキャラクターの判定が不明・曖昧なカードを「一致なし」とみなさない。5枚のいずれかが判定不能なら、通常カードのクリック前に指令を失敗させる。全ての通常枠が空文字列なら画像認識を行わず、従来の左端選択を使用する。

同名のキャラクターが前衛に複数いる場合、名前だけではそのカードの前衛位置を確定できない。区別に必要な識別情報がない間は、そのキャラクターを指す通常カード希望を実行せず失敗させる。前衛位置の追跡に失敗した場合、`members` の名前と認識結果を対応付けられない場合も失敗させる。通常カードの希望を持たない命令では、この照合を要求しない。

## 既存形式と実装境界

既存の `attack()`、`attack(0)`、`attack(2,0)` などは引き続き有効とする。数値引数は1枚目から順に宝具を指定したものとして扱い、残りの枠は空文字列とする。例えば `attack(2,0)` は `attack('N2','N0','')` と同じ選択になる。宝具番号の範囲・重複禁止・指定順、残りを通常カードの左端から選ぶ動作を維持する。旧形式のシナリオファイルは書き換えない。数値引数と文字列引数を混在させた命令は受け付けない。

フロントエンドは新形式を構文検証し、各枠の宝具指定または通常カード希望列として型付きコマンドへ変換する。バックエンドは受信した型付きコマンドを再検証する。元の命令文字列をバックエンドへ渡さない。新形式の型付きコマンドの具体的なフィールドとカード割り当て処理はR27、画面操作への統合はR28で実装する。R22では構文と実行時の意味を定義し、実装コードは変更しない。
