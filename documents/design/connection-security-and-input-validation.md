# 接続保護と入力検証

## 接続境界

FastAPI と Vite は既定で `127.0.0.1` のみに待ち受ける。バックエンド設定の
`host` は `127.0.0.1`、`localhost`、`::1` だけを許可し、全インターフェース公開を
拒否する。

許可 Origin は `AUTOFGO_CHROME_APP_URL` の Origin と完全一致する1件だけとする。
Origin が送信された要求はこの値を検証し、CORS 応答も同じ Origin、`GET` と `POST`、
必要な3ヘッダーだけを許可する。Origin がないローカルクライアントに対しても、後述の
セッショントークン認証は省略しない。

## 起動セッション

Python プロセスの起動ごとに UUID のセッションIDと `secrets.token_urlsafe(32)` の
セッショントークンを生成する。Chrome 起動時にはURLフラグメントで資格情報を渡す。
フラグメントはHTTP要求へ送られないため、アクセスログへ記録されない。フロントエンドは
初回読取直後に `history.replaceState` でフラグメントを消去し、メモリ内だけに保持する。

REST API と SSE は次の両ヘッダーを必須とする。

```http
X-AutoFgo-Session-Id: <session-id>
Authorization: Bearer <token>
```

バックエンドは固定時間比較で両方を検証する。認証エラーには資格情報を含めない。
Chrome または Python の終了処理ではトークンを無効化する。

## 入力上限

- API の要求ボディは 64 KiB 以下とする。
- API のパスとクエリ文字列の合計は 2,048 文字以下とする。
- 現在クエリ入力を持つAPIはないため、未知のクエリを拒否する。
- 操作指令受付以外のAPIでは要求ボディを拒否する。
- セッションIDは36文字以下、Authorization値は128文字以下とする。
- シナリオIDは既存の上限と正規化検証を維持する。
- 読み込むシナリオJSONファイルは 1 MiB 以下とする。
- 操作指令は Pydantic の strict モデル、未知フィールド拒否、命令別の値域制約で検証する。

上限超過、未知入力、認証失敗の応答は共通エラー形式とし、受信した秘密値や本文を
エラーへ転記しない。
