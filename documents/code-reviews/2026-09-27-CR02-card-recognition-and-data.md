## 確認できた指摘

### 1. 高: 認識したカードの名前と前衛が食い違っても左端のカードをクリックする

- 箇所: `backend/src/autofgo/card_selection.py:48-83`、呼び出しとクリックは `backend/src/autofgo/game_automation.py:233-269`。
- 成立条件: `frontMembers` が実画面の前衛と異なり、認識されたカードに前衛3人以外の名前が含まれる。選択処理は名前の集合を照合せず、希望に一致しない枠を左端の未使用カードで埋める。
- 再現: 前衛 `A, B, C`、5枚すべてを認識済みの `X`、指定を `B1, '', ''` として `select_cards` を実行すると、失敗せず位置 `0, 1, 2` を返した。実行経路ではこれを `cards.selected` として報告し、3枚をクリックする。
- 影響: 前衛追跡のずれ、ゲーム側の予期しない編成変更、誤った `frontMembers` を検出できず、希望と異なるカードを自動選択する。実画面での編成ずれは今回再現していない。
- 修正案: 通常カードの選択前に、認識済みの5枚すべての名前が正規化した前衛名に含まれることを検証する。不一致なら失敗させ、認識結果と前衛名を診断へ残す。希望カードが単に配られなかった場合の既定の左端補完は維持し、集合不一致の回帰テストを追加する。

### 2. 高: 複数の保存元が古いmanifestから保存すると参照が消える

- 箇所: `backend/src/autofgo/card_sampler.py:46-72`、`backend/src/autofgo/sampler_api.py:222-249`、`backend/src/autofgo/card_references.py:198-220`。サンプラーの `asyncio.Lock` はそのプロセス内だけで有効。
- 成立条件: サンプラーとCLIなど、2つの保存元が同じmanifestを読み、別々の名前または衣装の参照を採番して保存する。保存時にディスク上のmanifestが読込時から変わっていないか確認せず、最後の `os.replace` が前の更新を上書きする。
- 再現: 隔離した一時ディレクトリで空manifestを2回読み、`Alice` と `Bob` をそれぞれ採番した後に順に保存した。最終manifestのキャラクターは `Bob` だけで、画像ディレクトリには `Alice-1-01.png` と `Bob-1-01.png` の両方が残った。
- 影響: 登録成功と表示された参照が消え、PNGだけが孤立する。後の採番が既に使った番号を再利用する可能性もある。プレイヤーとの同時起動ではプレイヤーは読取側だが、CLIも共通の保存関数を使うため複数書き手は成立する。
- 修正案: 採番からmanifest置換までをプロセス間ロックで直列化し、ロック取得後にmanifestを再読込する。変更検知と再試行を併用し、異なる参照の並行保存が両方残るテストを追加する。

### 3. 高: 排他作成に負けた保存元が相手のPNGを削除し得る

- 箇所: `backend/src/autofgo/card_references.py:204-223`。
- 成立条件: `target.exists()` が偽だった直後、別の保存元が同じパスへPNGを作り終え、こちらの `target.open("xb")` が `FileExistsError` になる。例外処理は、この呼び出しがファイルを作成したかを確認せず `target.unlink()` する。
- 再現: 一時ディレクトリで存在確認と排他作成の間に別書き手のファイル作成を差し込むと、`FileExistsError` 後の `other_writer_file_exists` は `False` だった。
- 影響: 相手が保存したPNGが失われ、manifestがそのPNGを指すと次の参照読込や再生開始が失敗する。OS上で相手がまだ書き込み中の場合の削除可否は異なるが、書き込み後なら成立する。
- 修正案: 排他作成が成功したことを示すフラグまたは一意の一時PNGを使い、自分が所有するファイルだけをロールバックする。指摘2のプロセス間ロックも適用し、排他作成に負けた側が既存ファイルを残す回帰テストを追加する。

### 4. 中: 宝具の使用可否を確認せず座標をクリックする

- 箇所: `backend/src/autofgo/card_selection.py:54-57`、`backend/src/autofgo/game_automation.py:239-269`。
- 成立条件: `attack_cards` の枠に `N0`～`N2` があるが、対象の宝具を使えない画面状態。選択処理は指定をそのまま `np` にし、実行処理は撮影画像から使用可否を判定せず固定座標をクリックする。
- 影響: 設計資料が要求する「使用不可ならカードクリック前に停止」を満たさない。クリックが無効になるか別の画面要素へ作用するかは実画面で未確認で、後続選択とシナリオ進行が誤る可能性がある。
- 修正案: 宝具枠の表示と使用可能状態を検出し、指定した宝具が使えない場合は通常カードのクリック前に失敗させる。使用不可画像を用いた回帰テストを追加する。

### 5. 低: サンプラーと選択処理で `guest` 注釈の正規化が異なる

- 箇所: `backend/src/autofgo/sampler_api.py:57-59`、`backend/src/autofgo/card_selection.py:30-34`。
- 成立条件: シナリオの `members` が `A Guest` など大文字を含む末尾注釈を使う。選択側は大文字小文字を無視して `A` にするが、サンプラーは小文字の `" guest"` だけを除き、登録名を `A Guest` とする。
- 影響: サンプラーで登録した名前が実行時の前衛名と一致せず、カード希望が見つからない。現在のシナリオで確認した `guest` 表記は小文字のみ。
- 修正案: 正規化関数を共通化し、大文字・空白違いを同じ入力で検証する。
